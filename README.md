# speedtest

Консольная утилита: 10 раз подряд скачивает URL и печатает время и объём каждого запроса, среднее время, общий объём и скорость.

## Требования

Node.js 22+. Runtime-зависимостей нет: утилита — один файл `speedtest.js`.

## Запуск

Готовый файл — в [Releases](../../releases/latest):

```sh
curl -LO https://github.com/otmjka/speedtest/releases/latest/download/speedtest.js
node speedtest.js <url>
node speedtest.js --help
```

Или из исходников:

```sh
npm ci
npm run build
node release/speedtest.js <url>
```

Пример:

```text
$ node speedtest.js https://proof.ovh.net/files/10Mb.dat
Downloading https://proof.ovh.net/files/10Mb.dat 10 times...
Request  1/10: 3439.6 ms, 10485760 B (10.49 MB)
Request  2/10: 2127.6 ms, 10485760 B (10.49 MB)
...
Request 10/10: 1866.6 ms, 10485760 B (10.49 MB)

Average time: 2167.9 ms
Downloaded:   104.86 MB
Speed:        38.69 Mbit/s (4.84 MB/s)
```

## Единицы

Десятичные: 1 MB = 10^6 байт, 1 Mbit = 10^6 бит. `Mbit/s` — как у провайдеров, `MB/s` — как у браузеров при скачивании.

## Как меряем

- 10 GET строго по очереди: следующий — после полного получения тела предыдущего.
- Время запроса — от отправки до последнего байта тела. В первый запрос входят DNS, TCP и TLS, поэтому он обычно медленнее.
- Объём — реально полученные байты тела, не `Content-Length`.
- Скорость = все байты / сумма времён всех запросов.
- Заголовки `Cache-Control: no-cache` (просим не отдавать из кэша) и `Accept-Encoding: identity` (без сжатия, чтобы считать байты, которые реально пришли).
- Редиректы — проходим, меряем финальный ответ.

## Ограничения

- Маленький файл меряет задержку, а не канал. Берите файл от 10 MB.
- Соединение переиспользуется (keep-alive): запросы 2–10 идут без рукопожатий.
- Если сервер игнорирует `identity` и всё равно сжимает, считаются распакованные байты.
- Сервер может ограничить частоту запросов (HTTP 429) — это считается ошибкой.

## Ошибки и exit-коды

| Код | Когда                                                                                                                                                                 |
| --- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 0   | все 10 запросов прошли                                                                                                                                                |
| 1   | запрос упал: DNS/соединение/TLS, ответ не 2xx, обрыв тела, петля редиректов, 30 с без данных. Печатается `Request N failed: <причина>`, остальные запросы не делаются |
| 2   | плохой ввод: нет URL или их несколько, схема не `http`/`https`, нет схемы, логин/пароль в URL                                                                         |

Если все ответы пустые — итог с нулями и предупреждение в stderr, код 0.

## Разработка

```sh
npm ci
npm test          # тесты
npm run check     # формат, линт, типы, тесты с покрытием, сборка
npm run build     # esbuild → release/speedtest.js (один файл)
```

Перед каждым коммитом husky запускает `npm run check` (хук ставится сам при `npm ci`).

Релиз собирается сам: каждый push в `main` (мерж PR) → `npm run check` → GitHub Release `v0.1.<номер прогона>` с `speedtest.js`. `release/` в git не хранится.

Точка входа — `src/speedtest.ts`, модули — `src/lib/`, тесты — в `__tests__/` рядом с кодом, тестовый HTTP-сервер — `src/test-utils/`.
