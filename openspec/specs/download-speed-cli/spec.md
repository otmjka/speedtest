# download-speed-cli Specification

## Purpose
Консольная утилита: замеряет скорость скачивания, многократно запрашивая заданный URL, и печатает время и объём.

## Requirements

### Requirement: Аргумент URL
CLI MUST принимать ровно один аргумент — абсолютный `http:`/`https:` URL без логина/пароля. Иначе — usage в stderr, exit 2, запросов нет.

#### Scenario: Корректный URL
- **WHEN** `node release/speedtest.js https://example.com/big.jpg`
- **THEN** замер стартует

#### Scenario: Нет аргумента или лишние
- **WHEN** аргументов 0 или больше одного
- **THEN** usage, exit 2

#### Scenario: Чужая схема
- **WHEN** `ftp:`, `file:`, `data:`
- **THEN** ошибка с названием схемы, exit 2

#### Scenario: Без схемы
- **WHEN** `example.com/big.jpg`
- **THEN** подсказка «добавь https://», exit 2

#### Scenario: Логин в URL
- **WHEN** `https://user:pass@host/…`
- **THEN** ошибка «credentials не поддерживаются», exit 2

### Requirement: Справка
CLI MUST на `--help`/`-h` печатать usage в stdout и выходить с 0.

#### Scenario: --help
- **WHEN** `--help`
- **THEN** usage в stdout, exit 0, запросов нет

### Requirement: 10 последовательных запросов
CLI MUST делать ровно 10 GET; следующий — только после полного получения тела предыдущего.

#### Scenario: Последовательность
- **WHEN** все запросы успешны
- **THEN** сервер получил 10 запросов, одновременно — не больше одного

### Requirement: Заголовки
Каждый запрос MUST содержать `Cache-Control: no-cache` и `Accept-Encoding: identity`.

#### Scenario: Заголовки дошли
- **WHEN** запрос пришёл на сервер
- **THEN** оба заголовка есть

### Requirement: Редиректы
CLI MUST идти по редиректам и мерить финальный ответ; петля редиректов — ошибка запроса.

#### Scenario: 302
- **WHEN** 302 на ресурс 1 000 000 байт
- **THEN** запрос засчитан как 1 000 000 байт

### Requirement: Что меряем
По каждому запросу CLI MUST мерить время от отправки до последнего байта тела и число реально полученных байт тела (не `Content-Length`).

#### Scenario: Chunked без Content-Length
- **WHEN** сервер стримит 5 000 000 байт chunked
- **THEN** засчитано 5 000 000 байт

### Requirement: Вывод
CLI MUST печатать строку на запрос (номер, мс, размер, средняя скорость запроса в Mbit/s = байты запроса / его время) и итог: среднее время (мс), объём (MB), скорость (Mbit/s и MB/s) = все байты / сумма времён. Единицы десятичные (MB = 10^6 байт, Mbit = 10^6 бит). Exit 0.

#### Scenario: Математика
- **WHEN** 10 запросов по 1 000 000 байт за 100 мс
- **THEN** 100 мс, 10.00 MB, 80.00 Mbit/s (10.00 MB/s)

#### Scenario: Скорость запроса
- **WHEN** запрос: 104 857 600 байт за 23 815.8 мс
- **THEN** `Request  1/10: 23815.8 ms, 104857600 B (104.86 MB), 35.22 Mbit/s`

#### Scenario: Пустое тело
- **WHEN** все ответы пустые
- **THEN** 0 MB, скорость 0, в stderr предупреждение «ничего не скачано»

### Requirement: Ошибки
На первом упавшем запросе CLI MUST остановиться, напечатать в stderr `Request N failed: <причина>`, не печатать итог, exit 1. Падение: DNS/соединение/TLS, не-2xx, обрыв тела, петля редиректов, 30 с без данных (idle-таймаут).

#### Scenario: 500 на 3-м
- **WHEN** 3-й запрос → 500
- **THEN** сервер получил ровно 3 запроса, `Request 3 failed`, exit 1

#### Scenario: Зависание
- **WHEN** заголовки пришли, данных нет 30 с
- **THEN** запрос оборван, причина — таймаут, exit 1

#### Scenario: Медленно, но идёт
- **WHEN** загрузка дольше 30 с, но данные идут
- **THEN** не обрывается

#### Scenario: Обрыв тела
- **WHEN** сервер закрыл соединение до конца тела
- **THEN** запрос упал, exit 1

#### Scenario: Порт закрыт
- **WHEN** никто не слушает порт
- **THEN** `Request 1 failed`, exit 1

### Requirement: Размер файла
CLI MUST брать ожидаемый размер тела из `Content-Length` финального ответа до чтения тела. Размер считается неизвестным, если заголовка нет, он не целое неотрицательное число или ответ сжат (`Content-Encoding` не `identity`). Для замера по-прежнему MUST использоваться реально полученные байты.

#### Scenario: Заголовок есть
- **WHEN** ответ содержит `Content-Length: 14679474`
- **THEN** размер запроса известен — 14 679 474 байт

#### Scenario: Chunked
- **WHEN** в ответе нет `Content-Length`
- **THEN** размер неизвестен, замер работает как раньше

#### Scenario: Сжатый ответ
- **WHEN** ответ с `Content-Encoding: gzip`
- **THEN** размер неизвестен

### Requirement: Строка прогресса
Пока идёт запрос, CLI MUST показывать в stderr одну строку прогресса, перерисовываемую на месте: номер запроса из 10, полосу, скачано / всего в MB, процент, текущую скорость в Mbit/s. По завершении запроса строка прогресса MUST стираться, и печатается обычная строка запроса. Строка MUST укладываться в ширину терминала.

#### Scenario: Размер известен
- **WHEN** скачано 7 340 000 из 14 680 000 байт
- **THEN** строка вида `Request  3/10 [█████░░░░░]  50%   7.34 / 14.68 MB  62.0 Mbit/s`

#### Scenario: Размер неизвестен
- **WHEN** размер неизвестен
- **THEN** строка без полосы и процента: `Request  3/10  7.34 MB  62.0 Mbit/s`

#### Scenario: Запрос завершён
- **WHEN** запрос 3 дочитан
- **THEN** строки прогресса нет, есть `Request  3/10: …`

#### Scenario: Запрос упал
- **WHEN** запрос оборвался ошибкой
- **THEN** строка прогресса стёрта до вывода `Request N failed: …`

### Requirement: Текущая скорость
Текущая скорость MUST считаться по байтам за последнюю секунду (скользящее окно), а не от начала запроса. Пока данных меньше чем на окно — по фактическому интервалу.

#### Scenario: Скорость упала
- **WHEN** первые 5 с шли 10 MB/s, затем 1 с — 1 MB/s
- **THEN** показывается ≈ 8 Mbit/s, а не среднее за 6 с

### Requirement: Только для терминала
Прогресс MUST показываться только если stderr — TTY. Иначе вывод MUST совпадать с выводом без прогресса.

#### Scenario: Вывод в пайп
- **WHEN** stderr перенаправлен в файл или пайп
- **THEN** в stderr нет строк прогресса и управляющих последовательностей

### Requirement: Прогресс не влияет на замер
Перерисовка MUST быть не чаще 10 раз в секунду и не должна задерживать чтение тела.

#### Scenario: Много мелких чанков
- **WHEN** за секунду пришло 1000 чанков
- **THEN** строка перерисована не больше 10 раз
